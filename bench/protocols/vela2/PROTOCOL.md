# Reproduction and interpretation

Candidate and the required baseline use FP32. The baseline is the unchanged released FP32 ONNX graph with CPUExecutionProvider, ORT_ENABLE_ALL, ORT_SEQUENTIAL and intra-op budgets1/2/4; inter-op defaults are unchanged. The separate MLAS comparator uses its qualified packing/fusion/workspace configuration, aligned buffers, residual fusion and automatic partitioning. It is not replaced with a weaker default configuration.

The measured candidate uses strict oneDNN FP32 fpmath and accumulation, accurate softmax and GELU-erf. Rust implements some operations directly: embedding lookup, head/sequence gathers, YaRN/RoPE and query scaling, excluded-only masks, FP64 prefix accumulation rounded to FP32 endpoints, L2/cosine head arithmetic, calibration and decoding. Public oneDNN C API (`dnnl_*`) handles dense projections, residual sum post-ops, attention matrix products, normalization, softmax, activation/gating and weight reorder. There is no C++ bridge on the production path.

Compare identical tokenizer/configuration, six model inputs, task heads, postprocessing, batches and frozen requests. Keep tuning and held-out sets separate. The historical quality corpus had227 unique cases (168 tuning,55 held-out,5 long-window cases with one overlap), including117 Korean,79 English,31 mixed, choice/set/score/span tasks and complete API20. Independent preparation checked all six tensors. Decoded values/schema/errors agree; calibrated probabilities/scores must differ by no more than1e-4. Raw logit differences are reported separately. These inputs and their identifying labels/hashes are intentionally not published.

The final warmed matrix uses three fresh cohorts per backend/budget/scope, rotated order, five warmups and15 timed calls per cohort. Each reported cell pools45 samples with linear-interpolated empirical p50/p95/p99. Small-sample tails and cohort variability do not establish service-level guarantees or statistical significance. Every unfavorable cell remains in the aggregate report. A later independent tail study has120 samples per backend/case and remains distinct rather than replacing the original cells.

CPU affinity is one logical CPU per physical core by default (not 0..N−1, which on SMT guests pins sibling hyperthreads of the same core). Worker affinities are verified after cases against that cpuset. Any N≥1 is accepted. OMP ACTIVE, spin500, close binding, explicit places, Rayon frontend one thread and disabled tokenizer parallelism match. Compilation and measured inference jobs are serial. Concurrent contention is separately labeled and excluded from isolated results.

Model timing brackets internal forward after input conversion and before output serialization. API timing includes the same persistent JSON encode/write/read/decode boundary and complete frontend/model/decoder; API CPU sums controller and worker nanosecond process clocks. Throughput is rows divided by mean elapsed time; utilization is process CPU divided by elapsed time. Current worker RSS and current combined controller/worker RSS differ. Worker peak is lifetime VmHWM, including load and earlier cases, not an incremental case peak. The sum of individual peaks is only an upper bound on simultaneous peak memory. MiB=2^20 bytes.

Cold behavior means a fresh process with normal OS page cache; disk caches were not dropped. Startup/model packing/tokenizer initialization and first request are separate. First model forward uses internal timing; first API request uses the complete request boundary. Dedicated long cold fixtures avoid confusing later first-shape requests with fresh-process calls.

The extra contention experiment uses two two-thread workers sharing CPUs0,1, paired prepared-tensor JSON requests, and combined controller/both-worker CPU/RSS. Only this concurrency level is measured. No successful matched exact-S8192 latency result exists: the historical FP32 ONNX attempt exhausted available memory near13.94GB; windowed long8200 quality was evaluated. No production integration or Guard training follows from the experiment.

The published controllers consume independently supplied frozen request/oracle files and explicit worker commands. They do not include the private historical official-runtime adapters or fixture corpus. The ONNX worker supplies only the prepared-tensor baseline; complete API/preparation reference generation requires the separately obtained pinned official runtime. Comparing against a saved independent oracle is supported; generating that oracle with the candidate would invalidate quality claims.
